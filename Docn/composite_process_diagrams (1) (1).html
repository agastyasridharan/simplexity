Sequential composite belief state process

Extension of Shai et al. (2024) — hierarchical HMM with driver + transducer structure

1. Generative architecture

A hidden driver process selects between two Mess3 transducer variants at each timestep. Only the transducer's token emissions are visible to the transformer.

Key point: The driver state d_t is never observed. It selects which Mess3 variant governs the transducer at each timestep. The transducer emits visible tokens y_t ∈ {A, B, C}. The transformer must simultaneously infer (1) which driver regime is active and (2) what transducer state it's in — from the token stream alone.

2. Belief state decomposition

The 6D belief vector decomposes hierarchically into a driver marginal and two conditional transducer beliefs. Four linear probes target different components at different layers.

Update rule (identical form to original paper):
η_t = η_{t-1} · T_comp^(y_t) / (η_{t-1} · T_comp^(y_t) · 𝟏)

Block structure of T_comp^(y) encoding the hierarchy:
T_comp^(y) = | (1−ε)·T_A^(y)    ε·T_A^(y)    |
                 |  ε·T_B^(y)      (1−ε)·T_B^(y) |

Critical: Top-right block uses T_A (not T_B) — the current driver state determines transducer dynamics.

3. Expected geometry and predictions

The belief geometry should show two fractal attractors (one per regime) connected by a bridge of uncertain-driver points. The synchronization timescales should separate cleanly.

Left: Expected belief geometry projected from the 5-simplex. Two fractal clusters (one per driver regime) separated along the driver-belief axis, connected by a bridge of uncertain-driver points from early context positions.

Right: Predicted probe MSE vs. context position. The transducer synchronizes within ~3 tokens (directly observable). The driver synchronizes over ~20 tokens (requires multi-token statistical evidence). The full belief MSE is bottlenecked by the driver — this timescale separation is the central novel prediction.
