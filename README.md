# Belief-state decomposition in transformers

This repository studies whether transformers trained on sequences from composite processes represent the beliefs about each component in their residual stream. It builds on [Shai et al., *Transformers Represent Belief State Geometry in their Residual Stream*](https://arxiv.org/abs/2405.15943), using a fork of [Astera's Simplexity library](https://github.com/Astera-org/simplexity).

In brief, the paper trains small transformers on sequences generated by hidden Markov models, then uses linear probes to recover the Bayesian posterior over hidden states. Because the generating process is known, we can calculate that posterior exactly and compare it with the model's representations. We extend this to processes with multiple interacting components:

1. We train on a hierarchical HMM, where a slow hidden driver switches between two Mess3 processes, and ask how the driver and transducer beliefs become readable across layers.
2. We construct an explicit input–output process: an input HMM emits a symbol `y`, and a transducer with its own hidden state reads `y` and emits `x`. We train on pairs `(y, x)` and probe for the input, transducer, and joint beliefs.
3. We hide the intermediate symbol `y` and train on `x` alone. This changes what an observer can infer. We test whether the model represents the resulting belief geometry, and how much of the fully observed belief remains linearly recoverable.

The [slides](docs/slides/transducer_experiment.pdf) give the overview. The [results report](Docn/Result%20Doc/main.tex) contains the experiments, figures, and interpretations; the [experiment guide](docs/transducer_decomposition_experiment.md) explains the construction and how to run it.

### Results so far

For the tested processes, the analytical joint belief factors into input and transducer beliefs when both streams are observed. Hiding the intermediate symbol generally makes those beliefs statistically dependent.

With both streams observed, linear probes recover the input and transducer beliefs at R² ≈ 0.99 on both SNS (Simple Nonunifilar Source) and Fractal2 processes. These runs use a four-layer transformer trained for 100,000 steps. The values below use activations concatenated across all four layers.

| Process | Both streams: input R² | Both streams: transducer R² | Output only: fully observed input R² | Output only: fully observed transducer R² |
| --- | ---: | ---: | ---: | ---: |
| SNS → SNS | 0.990 | 0.992 | 0.050 | 0.89 |
| Fractal2 → Fractal2 | 0.997 | 0.995 | 0.017 | 0.92 |

The last two columns ask a different question from ordinary belief recovery: can an output-only model recover the posterior that an observer seeing **both** streams would have? It recovers much of the transducer belief, but little of the input belief. The output-only model can still encode its own, less informed posterior accurately. Low cross-observation R² is not by itself a measure of information erased or evidence that the model discarded information available in its input.

The experiments include untrained-model, shuffled-target, sequence-held-out, and position-split controls. In an unpredictable Fractal2 control, training adds little to belief recovery (R² 0.76 versus 0.73 untrained). These are linear-readout results; they do not establish that the transformer implements the generator's causal sequence across its layers. The feedback experiment is implemented but remains a next step in the report.

### Running the experiments

The Colab notebooks are the simplest entry point. Select a GPU runtime, run the dependency cell, and choose the process and observation regime in the configuration cell. Keep `COLAB_FREE_T4 = True` for the 100,000-step configuration used in the transducer report. Use either the training cell or the checkpoint-loading cell, then run the analysis. The [experiment guide](docs/transducer_decomposition_experiment.md#running) has the details.

For the full library, use Python 3.12+ and [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
git clone https://github.com/agastyasridharan/simplexity.git
cd simplexity
uv sync --extra dev
```

The library uses Hydra configurations under `simplexity/configs/`. The transducer notebooks contain their own configuration and do not require the library's JAX training stack.
